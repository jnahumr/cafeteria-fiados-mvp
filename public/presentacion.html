El problema

Un cuaderno de papel que no cuadra

En muchos negocios pequeños de Honduras, el fiado —dejar que un cliente se lleve productos y pague después— se sigue anotando en una hoja de papel. Ese método falla constantemente. Cada cliente se anota a sí mismo lo que se lleva y muchas veces no lo hace; la hoja se moja, se rompe o se pierde; y la letra no siempre se entiende. Al cierre del mes las cuentas no cuadran, nadie sabe con certeza quién debe cuánto, y el negocio termina asumiendo pérdidas de dinero por puro descontrol.

El costo no es solo económico. La persona a cargo pierde tiempo valioso sumando a mano cada saldo, y aun así no puede confiar en el resultado. Cuando un cliente discute lo que debe, no hay un registro claro que respalde la cifra, lo que genera desconfianza y hasta discusiones. Es un problema real, cotidiano, y que se repite en miles de pulperías y cafeterías del país. Automatizarlo bien no es un lujo: es la diferencia entre un negocio ordenado y uno que pierde plata sin darse cuenta.

La solución

Control de Créditos

Control de Créditos es una aplicación web instalable (PWA) que reemplaza el cuaderno de fiados por un registro digital confiable. La persona a cargo registra cada fiado y cada abono, y el sistema lleva el saldo de cada cliente de forma automática y exacta. Ya no depende de que el cliente se anote ni de sumar a mano: en cualquier momento se sabe quién debe cuánto, con el detalle de qué productos se llevó y a qué precio.

Está pensada para el día a día real de un negocio pequeño: se usa desde el celular, es simple, y funciona como una app instalada aunque la conexión sea inestable. En vez de exigir un equipo caro o conocimientos técnicos, ofrece una herramienta que cualquier persona a cargo del mostrador puede usar en segundos, mientras atiende.

Funcionalidades

Qué hace la aplicación

La aplicación cubre todo el ciclo del fiado, del registro al cobro:

  • Registro de fiados y abonos por cliente, con el detalle de productos, cantidad y precio.
  • Saldo automático: cada movimiento actualiza al instante lo que el cliente debe.
  • Precio congelado: cada fiado guarda el precio del momento de la venta, así el histórico no se altera si más adelante cambian los precios del catálogo.
  • Catálogo de productos propio de cada negocio, fácil de mantener.
  • Búsqueda de clientes tolerante a mayúsculas y acentos, para no crear duplicados.
  • Cobro por WhatsApp: genera un recordatorio con el saldo del cliente y se envía con un solo toque.
  • Roles de dueña y empleado, con permisos distintos según la responsabilidad.
  • Multi-negocio: varias cafeterías usan la misma aplicación, cada una completamente aislada de las demás.
  • PWA instalable con soporte offline del entorno de la aplicación.
Arquitectura

Cómo está construida

El producto sigue un patrón moderno de PWA sobre servicios gestionados. El frontend es una Single Page Application hecha con React y Vite, desplegada en Vercel (PaaS), que se encarga del build, el HTTPS, la CDN y los despliegues automáticos en cada cambio. El backend es Supabase (BaaS): una base de datos PostgreSQL gestionada, autenticación lista para usar (correo y Google) y seguridad a nivel de fila.

La decisión de arquitectura más importante fue el aislamiento entre negocios. En lugar de programarlo en el código de la aplicación —donde un error se cuela fácil— se declara directamente en la base de datos con Row Level Security y la función mi_negocio_id(). Así, cada usuario solo puede ver y modificar los datos de su propio negocio, sin importar qué haga la interfaz. Elegí servicios gestionados a propósito: siendo un desarrollador solo, me permiten entregar rápido, sin costos de servidores y con seguridad seria desde el primer día.

Más allá del stack, el proyecto se construyó con prácticas de ingeniería reales. Incluye un pipeline de integración continua en GitHub Actions que corre lint, pruebas unitarias y build en cada cambio, con la rama principal protegida para que ningún código roto llegue a producción. La calidad se mide de forma objetiva con SonarCloud (cero bugs, cero vulnerabilidades y duplicación controlada), y las pruebas cubren la lógica de negocio crítica, como el cálculo del saldo de cada cliente.

Manual de uso

Cómo se usa, paso a paso

  1. Iniciá sesión con tu correo o con tu cuenta de Google.
  2. Cargá tus productos en el catálogo, con nombre y precio.
  3. Agregá o buscá al cliente al que le vas a fiar.
  4. Registrá el fiado: elegí los productos y la cantidad; el sistema calcula el monto solo.
  5. Registrá el abono cuando el cliente pague, sea total o parcial.
  6. Consultá el saldo: se actualiza automáticamente y muestra con claridad quién debe cuánto.
  7. Cobrá por WhatsApp enviando el recordatorio del saldo con un solo toque.

Todo el flujo está diseñado para hacerse en pocos segundos desde el celular, sin interrumpir la atención al cliente.

Cliente

Un negocio real usándola hoy

El usuario real de Control de Créditos es la cafetería de la Asociación de Empleados Infra, en el Barrio Las Acacias, San Pedro Sula, que vende refrescos, snacks y pan dulce a los empleados. Llegué a ellos a través de una amiga que trabaja ahí y que me pidió una solución, porque llevaban los fiados en una hoja de papel donde cada cliente se anotaba solo, con el descontrol y las pérdidas que eso traía.

Hoy la aplicación está en producción y en uso real, con los productos y clientes de la cafetería. Fue diseñada originalmente pensando también en la cafetería de comida casera de un familiar, que la adoptará próximamente, y su arquitectura multi-negocio permite que más locales la usen sin cambios.
